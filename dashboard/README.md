# Training Dashboard

A static HTML/CSS/JS dashboard that aggregates every training run under
`results/` into one browsable interface. **No server required** beyond
Python's stdlib `http.server`.

## What it shows

- **Cross-run comparison.** Test Gini and Test MAE per architecture × run,
  side by side. KPI cards for the best-known Gini per dataset. Optuna
  tuning lift table comparing v2 untuned vs v4 tuned for House Prices.
- **Kaggle leaderboard view.** Our best test metrics against publicly
  known Kaggle leaderboard ranges, with explicit caveats about the
  split difference (we use 80/20 of `train.csv`; Kaggle scores on
  held-out `test.csv`).
- **Per-run detail.** Click any run in the sidebar to see its full
  metric table (sorted by Gini, with the best/worst values highlighted),
  a Gini-vs-`n_params` scatter, training time per architecture, top-15
  feature importance per model (if interpretability was computed),
  and LocalGLMnet's per-row coefficient stability table.
- **Live training monitor.** A separate page (`live.html`) that polls
  the active training log every 2 seconds and renders epoch-level loss
  curves + Optuna best-score per trial, with a status badge showing
  whether the run is training, complete, or in error.

## Quick start

```bash
# 1. From the repo root, regenerate the data:
python scripts/build_dashboard.py

# 2. Start a static server from the repo root (NOT the dashboard dir -
#    the live monitor needs to fetch ../<logfile>.log).
python -m http.server 8000

# 3. Open:
# http://localhost:8000/dashboard/index.html      <- main dashboard
# http://localhost:8000/dashboard/live.html       <- live training monitor
```

To watch an active training run, open `live.html` and paste the path
to its log file (e.g. `hp_tuned.log`, `allstate_training.log`, or any
custom name). The page polls the file every 2 seconds.

## How the data flow works

```
results/<run_id>/                          dashboard/runs.json
├── evaluation_summary.csv  ─────────────┐
├── model_summary.json      ─────────────┤
├── feature_importance.csv  ─────────────┼─> build_dashboard.py
├── localglmnet_coefficients.csv ────────┘   parses + emits one JSON
├── dashboard_dl_models.html (existed)
└── dashboard_dl_interpretability.html (existed)
```

`build_dashboard.py` is deterministic - it walks `results/`, parses
what it finds, and produces a versioned `runs.json` with all metrics,
configs, feature importances, and LocalGLMnet coefficient summaries.
The frontend reads `runs.json` once at page load and renders entirely
client-side via [Plotly.js](https://plotly.com/javascript/).

## Refresh after a new training run

```bash
python scripts/build_dashboard.py
```

Then reload the dashboard in the browser (no server restart needed).

## Why not use the existing `dashboard_dl_models.html`?

Each training run produces its own self-contained Plotly HTML
(`dashboard_dl_models.html`, `dashboard_dl_interpretability.html`) -
those are great for inspecting a single run in depth. The dashboard
here is for **comparing across runs** and getting a quick overview
of the whole training history, which the per-run HTMLs don't do.

You can still open the per-run dashboards directly:

```bash
open results/house_prices_8arch_interp/dashboard_dl_interpretability.html
```

## Live training monitor - protocol

The live monitor parses these log lines (all emitted by
`modelling/training.py` and `modelling/tuning.py`):

| Pattern | Extracted info |
|---|---|
| `[<arch>_m<N>] Epoch <n>/<total> - train_loss=... val_loss=...` | per-epoch losses |
| `Training: <ARCH>` | current architecture |
| `[<arch>] DONE in <s>s - Test Gini=... \| MAE=... \| A/E=...` | architecture complete |
| `<arch> best trial #<n> (RMSE=... \| val_deviance=...)` | Optuna best-trial-so-far |
| `Pipeline finished in <s>s` | full pipeline complete |

The monitor re-parses the entire file every 2s rather than incremental
tail - simpler and the log files stay small.
